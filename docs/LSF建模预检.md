# LSF 建模预检：先看真实结构，不运行 FDTD

“仅建模检查（不求解）”在本机 Lumerical CAD 中创建各扫描点的模型，读取实际对象尺寸和材料，检查输入是否生效，并比较不同扫描点的结构变化。它与“规划并保存”不同：规划只生成脚本，预检会实际执行可安全分离的建模部分；预检不计算电磁场、Jones 系数或衍射效率。

## 在界面中操作

1. 重新打开项目根目录的 `LSF_JSON_GUI.cmd`，导入可运行的 LSF。
2. 选择扫描变量、数值列表及固定参数，选择输出目录。需要材料库或其他依赖时，在高级设置中添加相应文件。
3. 点击“仅建模检查（不求解）”。任务记录会自动保存，不必手写 JSON，也不用先启动求解队列。
4. 查看日志中的 `PRECHECK`。此阶段可能启动 Lumerical CAD；这不表示正在运行 FDTD 求解。
5. 点击“打开输出目录”，进入 `preflight` 下本次时间戳文件夹，打开 `report.html`。按报告中的链接查看原生 `model.fsp`、对象记录与 `geometry_XY.png`。这张图由实际 CAD 属性绘制 XY 矩形投影，不是 Lumerical 原生截图。
6. 如需中断，点击“停止”，等待当前预检队列清理自己启动的进程。再次检查时重新点击预检按钮，每次检查单独保存。

当前 AH53 XY 示例使用兼容源 `lsf_exports/acceptance_source/02_AH53_XY_FDTD_v252.lsf`：固定 `film_count=1`，保持原 `film_mode(1)=1`，扫描 `film_t_nm(1)=0,100,200`。这里的 0 nm 是无覆盖膜，100、200 nm 是原脚本的阶梯共形包覆。该示例实际为二维 XY，不是三维验证。

## 看报告时核对什么

| 内容 | 应当如何理解 |
|---|---|
| 输入值 | 对照本次扫描值、固定值和原脚本单位，检查覆盖是否真正进入建模过程 |
| 对象与尺寸 | 核对 CAD 中的实际坐标、跨度、对象数量及可读取的几何属性 |
| 材料 | 核对对象实际采用的材料名称或对象定义折射率；这不等于完成材料色散精度验收 |
| 扫描点之间的变化 | 看目标层厚度、表面位置、相关对象是否按原脚本关系变化；若尺寸没有变化，需要查输入是否参与了目标几何 |
| 光源和监视器位置 | 检查是否有与结构位置有关的提示，尤其是增加膜厚后的相对位置 |
| `geometry_XY.png` | 根据实际 CAD 属性绘制的 XY 矩形投影，用于辅助查看位置和尺寸；不是原生截图，不能确认未知、曲面或旋转对象的实际形状 |
| `model.fsp` | 保存的原生 CAD 模型，复杂几何、隐藏界面或投影无法说明的内容应打开它复核 |
| 检查结论 | 只覆盖报告明确列出的规则和可读取属性，不表示电磁精度或未知设计意图符合要求 |

通用检查可以告诉你“模型实际是什么、扫描前后变了什么”。特定结构的预期关系，例如某一层应该随下层移动多少，必须来自已知脚本规则或明确的设计约定。程序不会仅凭变量名是 `thickness` 就断言所有上层都应刚性平移。只有源文本 SHA-256 与已知 AH53 XY 源匹配时，才采用该结构的独立数学几何规则；其他脚本使用通用检查，不能自动确认的内容显示 REVIEW，表示待确认。

**包围盒相交不能直接等同于材料实体重叠。** 对旋转、多边形、曲面或其他复杂对象，包围盒只是一种外部范围；重叠提示应结合对象实际几何、材料优先级和原生 CAD 查看，不作为任意三维实体相交的证明。属性投影和原生截图也不能证明所有隐藏界面、微小间隙或网格细节都正确。

本机使用隐藏 CAD（`hide=True`）时，`exportview` 在中文路径及纯 ASCII 临时路径上均未成功，因此默认预检不反复尝试截图，而是提供明确标注的属性投影。命令行增加 `--visible` 时才诊断性地尝试原生 XY 视图；三维模型还会尝试 XZ/YZ 视图。原生视图导出失败独立记录为 WARN，不能算作截图通过；仍可打开 `model.fsp` 手动查看。

## 无求解入口的边界

预检必须能够可靠区分建模与求解。当前接受以下两种建模结束边界：

- 顶层独占一行的 `# AH53_BUILD_ONLY_END` 注释，放在完整建模结束、任何求解或后处理之前；不能切断表达式或控制语句。
- 唯一、受支持的顶层 `if (run_solver==0) {...} else {...}` 完整分支之前，如当前 AH53 示例。

程序只执行边界之前、通过命令白名单核对的建模前缀。未知命令、`eval`/`feval` 等动态执行、任意函数、组 setup 脚本或动态加载不会猜测放行。添加边界标记不能绕过这些限制。不能安全分离的脚本需要先整理，单纯全局删除文本里的 `run`，或只把一个叫 `run_solver` 的变量改成 0，都不足以保证任意脚本不会求解。

预检不会为了绕过失败而执行完整求解脚本，也不会把缺失的建模证据填成成功。原脚本的语法、版本不兼容、无效材料或缺失依赖仍可能让 CAD 建模失败，应按本次预检日志修正。

这不是完整 LSF 编译器。建模段会交给原生 CAD 实际执行并检查几何；求解和后处理段未执行，因此不能宣称整个原脚本的所有语法、数据读取和结果分析均已验证。

每次预检写到：

```text
<任务输出目录>/
  task.json
  preflight/
    <本次时间戳>/
      report.html
      ...本次案例及建模证据...
```

原求解案例的 DONE、原生结果与求解报告不因预检被改写。预检完成也不会让尚未求解的案例变成求解 DONE。需要求解时，再点击“启动 / 续跑队列”。

## 命令行

以下使用界面已经保存的任务记录，只进行建模预检：

```powershell
Set-Location -LiteralPath 'D:\工作\AH53_Experiment_Runner_v2'
$lumPython = 'D:/Ansys Inc/v252/Lumerical/python/python.exe'

& $lumPython run_experiments.py preflight `
  --config 'output_lsf_film_scan/task.json'
```

将配置路径换成自己的 `task.json`。预检报告具体位置会写入日志。当前命令针对完整 LSF 扫描格式；可选 AH53 二维 JSON 模板继续使用其原有规划与检查流程。

仅在需要显示 CAD 和诊断原生视图导出时，为上面的 `preflight` 命令添加 `--visible`。这个选项不会启用 FDTD 求解；原生视图是否成功以本次报告为准。

## 2026-10-24 本机实测

使用 v252 / 2025 R2（会话版本 `8.34.4175`）的原生 CAD，仅执行通过安全检查的建模段，没有运行 FDTD。每个案例约 27 秒，包含独立 CAD 会话启动、属性读取和保存。

| 案例 | 实际检查结果 |
|---|---|
| 一层共形膜，0 / 100 / 200 nm | 三点均 PASS；条纹、材料分区、侧壁覆盖、层间空隙/交叠、顶面及固定源/监视器关系通过已知 AH53 规则 |
| 两层：下层共形膜 100 / 200 nm，上层平坦化膜固定 150 nm | 两点均 PASS；实际总顶面分别为 550 / 650 nm，逐区材料分布匹配期望，不只比较最高点 |
| 反例：`film_count=0`，却扫描 `film_t_nm(1)=100` | CAD 可以建模，但预检为 FAIL，明确指出被扫描膜未启用；不会把“程序能运行”算作扫描有效 |

- `output_lsf_preflight_two_layers/preflight/20261024_111253_9e082d/report.html`

完整验收记录为 `local_validation/lsf_preflight_acceptance.json`。六个案例均有建模脚本、实际 CAD 属性、工程、规则检查和投影图；原先的三点 FDTD 求解产物再次通过完整性核验，未被预检覆盖。

55 项相关离线回归通过，其中几何反例包含“顶面不变但侧壁漏膜”“上层位置错误导致交叠”等。真实 Tk 控件的预检按钮也完成了调度冒烟检查；该按钮测试模拟了子进程，不作为 CAD 结果证据，CAD 证据来自上述六个实际建模案例。
